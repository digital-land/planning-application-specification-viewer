Data model

The planning application data standard describes what applicants submit, what planning authorities record and what information is made available for others to use.

Select a marker to explore each part and how it connects to the others.

A submission provides the starting information. The authority maintains records as the application progresses. Views select information from those records for particular purposes, including publication as open data.

How an application submission is structured

An application type brings together modules. Modules group related fields and can use components to reuse groups of fields. Modules can also contain fields directly. Fields define individual items of information and can link to codelists that set allowed values.

Conditional rules explain when information applies or is required. For example, one answer can make another field relevant.

Example structure: application type → module → component → field. A module can also link directly to a field.

How planning authorities record information

A dataset describes one kind of thing. It contains records for that thing, with fields describing each record and references connecting related records. For example, a planning application can link to a site, and a decision notice can link to its application.

Datasets describe the information authorities maintain. They do not prescribe how an authority must arrange its internal systems.

How views select information

A view selects datasets, fields and records for a purpose. The national public view defines the planning data to make available as open data. It is a selected part of the wider information authorities record.

Read about the national public view.

Shared definitions

Fields and codelists are shared building blocks. A field describes an item of information and its datatype. A codelist gives the controlled values that can be used for a field.

Browse the field and codelist indexes.

Why information is included

User needs describe what people need to achieve. Justification records explain how parts of the data model support those needs. Design decisions record why the model uses a particular approach.
